### Current temporary and Docker-resource ownership

- `install.py:1065-1084` owns host `TemporaryDirectory` roots prefixed `sub2api-build-` and `sub2api-release-`; restore/install records also use `codex-eval-restore-` and `codex-eval-install-` (`:795,1044`). Normal exit removes these automatically. A cleanup command should consider only stale directories under the active system temp root, report exact paths/ages/sizes, skip active/locked workspaces, and require explicit selection before deleting an unmarked leftover.
- The installer names transient tool probes `codexeval-tool-<uuid>` (`:348-387`), HTTP probes `codexeval-http-<uuid>` with `--rm` (`:505-513,585-601`), and source helpers `codexeval-source-<uuid>` that own `/tmp/codexeval-source.*` scratch (`:733-760`). Normal cleanup targets those exact names. Orphans with these unique prefixes are reasonable cleanup candidates after confirming they are stopped and not owned by a live installer; never match by a loose substring.
- The Buildx path creates a unique `codexeval-builder-<uuid>` and removes that exact builder in `finally` (`install.py:945-971`). A cleanup command may enumerate exact names with this prefix and offer those stale builders for removal. Leave shared builders such as `desktop-linux` untouched.
- The no-Buildx fallback creates unnamed Go and Node containers from digest-pinned images and stores their IDs only in process memory; `finally` removes those exact IDs (`install.py:887-915`). After a crash, these containers have no Codex ownership label/name. New creation paths should add a task/run ID label (and attributable name); historical anonymous containers should be listed by exact ID, inspect facts and require explicit user selection before `docker rm`.
- Go and Node tool images (`golang:<declared-go>-alpine`, `node:24-alpine`) are ordinary shared images inspected/pulled by digest (`:348-405,929-944`), not installer-owned caches. The cached `alpine/git:2.49.1` image is the current source/probe helper (`SOURCE_TOOL_IMAGE`, `:339-346`) and should be preserved for the new installer. Enumerate unused Go/Node image IDs, digests, tags, size and container references; remove only an explicitly selected exact image ID after confirming no container/build uses it. Do not run `docker image prune`, `docker system prune`, or remove volumes/application containers.
- `adapter/Dockerfile:1-14` consumes the Go/Node images and copies source/plugin into a disposable build stage. Current workflow cleanup already removes the named Buildx builder and fallback containers on normal completion. No persistent project-owned module/cache volume is configured in this Dockerfile.

### Package and transaction notes

The current package is enforced by `universal_payload.SOURCES`, consumed by `scripts/package-sub2api.py`; a new standalone `cleanup.py` must be added to that allowlist and covered by package/archive tests or packaging will reject it. Use the same Python standard library and Docker CLI conventions. Keep cleanup separate from install/rollback state changes: remove only exact installer-owned resources or user-selected unowned cache IDs, never global Docker state.

A useful default is to inventory exact stale temp paths and `codexeval-builder-*` names with age/size and current-use checks, then ask once before removing those candidates. Also list anonymous fallback container IDs and unused Go/Node image IDs/digests/sizes for explicit interactive selection or exact-ID flags. Preserve active/ambiguous items and `alpine/git`; report their reason instead of silently skipping the entire cleanup operation.
