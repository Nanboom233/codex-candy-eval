# Sub2API v0.2.16 破坏性变更方案

用户要求：删除所有兼容配置，一切按破坏性变更处理，重新给出修改列表。
本文件替代上一轮84项清单作为新方案；旧清单仍是现状证据。任务保持 planning，以下是拟修改内容，尚未批量删除产品代码或生成新安装包。每项具体实施仍逐个审批。

## 固定边界

仅针对已核实的 Sub2API v0.2.16、Linux/amd64。开发端按上游 Go1.27.2、Node20、pnpm9构建；用户机器只替换预编译二进制。
不支持旧插件API、CPA凭据格式、旧状态格式、旧记账身份、其他Sub2API版本或备用实现路径。不自动转换、合并、修复旧数据。
删除兼容代码不等于删除用户数据库、已有API Key或原始历史文件；本轮没有批准这类数据清除操作。
精确选账户、正常账单/限额/并发、四种原评估及管理页面仍是待逐项核对的功能边界。破坏性变更不作为绕过这些原生行为的理由。

## 剩余拟修改项

| ID | 修改内容 | 范围限制 |
| --- | --- | --- |
| P01 | 固定v0.2.16的评估依赖注册 | 接入Application/Service/Handler；使用该版本的Wire生成方式，无动态结构适配。 |
| P02 | 管理员评估API | 状态、目标、启动、取消、历史、清空、停用；直接使用原生管理员鉴权和响应格式。激活/Key创建是否独立保留，归P05具体审批。 |
| P03 | 账户及分组选择 | 使用原生读取服务，提交明确group_id/account_id；不保留CPA credential转换。 |
| P04 | 精确账户Responses执行 | 仅固定版本中实际走到的入口/调度路径，禁止评估切换账户；保留正常限额、并发、权限和取消。实际必要的钩子逐条审批，不以组名自动批准全部旧修改。 |
| P05 | 原生用量和记账接入 | 使用原生账单路径；如保留当前记账Key机制，仅保留当前格式创建/使用/停用和必要的查漏值隔离，不迁移旧身份。具体生命周期仍单独审批。 |
| P06 | 四种评估执行 | 保留Candy、Fingerprint、ModelTrace、Pelican原题目、算法、阈值和数据，只改宿主调用；额外参数限制、解析边界等旧修改逐条审定，不默认全保留。 |
| P07 | 运行状态和历史 | 单一新格式的启动、进度、取消、结果保存和读取；旧格式不转换。活动意图/重启恢复作为子项单独审批，非默认新增要求。 |
| P08 | 原生管理页面 | 一条直接入口，使用新API/字段、管理员会话、分组/账户和模型选择、原评估展示；不用旧路径转换或模型目录兼容层。nonce/CSP及Pelican展示只保留实际需要的内容。 |
| P09 | 取消及退出接入 | 接入必要的评估取消和原生清理流程；沿用原生server监听方式，去掉无限五秒重试。等待策略具体审批，不增加新框架。 |
| P10 | 预编译二进制替换脚本 | 明确选容器、备份、替换、重启、失败恢复；采用固定部署路径，保留完整原始错误和操作进度，不拉源码/编译/引入探测镜像。 |
| P11 | 开发端构建和安装包 | 固定源码普通patch、上游构建、许可证和明确安装文件；统一dist/build/sub2api-codex-*输出，无兼容清单、来源证明或额外类型门禁。 |
| P12 | 独立旧构建资源清理脚本 | 保留用户明确要求的独立脚本并打包；只针对之前引入的可归属资源，不扩展成通用镜像清理器。 |

## 行为变化

旧API、旧状态和旧身份不提供兼容。旧插件状态不自动沿用。回滚/卸载恢复程序二进制，不等同于删除记账行或历史数据；原生管理员API仍是账单/Key管理入口。
单版本新页面和新接口一起切换，无双写、双读、旧字段别名或自动修复流程。
仅使用上游规定检查及用户明确批准的验收。新增方案清单不是新增验收门槛。

用户已确定破坏性变更及删除兼容配置的方向。D/P各项是整理后的实施范围，不代表已批准全部实现细节。
上轮C29的单行方案暂停，纳入D08整体核对；不提前实施一个最终会被替换的旧UI局部补丁。
后续按具体子项逐一审批，特别是P04所需宿主钩子、P05记账生命周期、P07状态字段以及D10取消自动维护撤销的行为变化。
