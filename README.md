# Codex 降智测试

在 Sub2API 管理面板中跨多供应商（OpenAI、Anthropic、Gemini、Antigravity）使用糖果测试、指纹检测、鹈鹕测试和 SIWC 授权状态检测。

## 使用

1. 登录 Sub2API 管理面板。
2. 打开侧栏中的「账户评估」。
3. 选择「糖果」「指纹」「鹈鹕」或「SIWC」。
4. 选择账户分组，并可按供应商和凭证类型（如 `OpenAI · OAuth`、`Anthropic · API Key`、`Gemini · API Key`、`Antigravity · API Key`）筛选账户。

账户右侧的「测试」或「检测」按钮用于单账户操作，列表上方的「测试全部」或「测试所选」用于批量操作。勾选账户后，批量操作只作用于所选账户。未勾选时，批量操作作用于当前筛选下的全部可用账户。
模型列表支持选择已有模型，也可以通过「自定义模型…」输入完整模型名称。
账户右侧的「启用」开关会直接修改该账户在 Sub2API 中的可调度状态。

### 糖果测试

1. 选择模型。
2. 选择推理强度。
3. 设置每账户次数。
4. 点击「测试」。

糖果题的正确答案是 **21**。展开账户可查看历次回答。正确率按当前选择的模型和推理强度统计。

### 指纹检测

1. 选择模型。
2. 设置每账户并发，范围为 1–3。
3. 点击「测试」。

每轮随机选择三道数字挑战，与参考库中的候选模型比对。结果显示最接近的模型和排名。
三道挑战均得到有效回答时显示概率。只有部分回答有效时，概率显示为「—」。
结果为「不像语言模型回答」时不显示排名。展开账户可查看历史记录，点击「查看详情」可查看候选模型排行、挑战回答和尝试次数。

### 鹈鹕测试

1. 选择模型。
2. 选择推理强度。
3. 选择「原版」或「多合一版」。
4. 点击「测试」。

原版生成鹈鹕骑自行车的 HTML 动画。多合一版生成 SVG 图片，加入孙悟空、秦始皇和北极熊，并让鹈鹕喊出糖果题的答案。
切换版本会更新「查看题目」中的内容，并保存选择。

列表和历史记录显示画面缩略图，点击可放大查看。最近一次结果、历史记录和详情均显示该次测试的版本。
两种版本共用每账户最近 20 条鹈鹕记录。画面内容和其中的糖果答案由用户判断。

### SIWC 检测

1. 选择包含 OpenAI OAuth 账户的分组。
2. 选择模型。
3. 点击单账户「检测」或批量「检测全部」/「检测所选」。

SIWC 检测仅适用于 OpenAI OAuth 账户，每个账户发送 1 次简短 Responses 请求（插件不重试），并根据返回结果或错误码判定账户状态（`SIWC 可用`、`订阅共享受限`、`额度或频率受限`、`认证异常` 等）。展开账户可查看历次检测记录，点击「查看详情」可查看详细状态与错误码。

### 记录、额度与停止

测试会消耗供应商额度。失败或无法使用的回答可能触发重试，每个请求最多尝试三次。糖果题答错不重试，除 408 外的 4xx 错误（如身份认证失败和限流）也不重试。耗时和用量包含所有尝试。
每个账户的每种测试保留最近 20 次记录，刷新或重启后仍可查看。

标签栏右侧的垃圾桶清空全部测试记录。账户列表右上角的垃圾桶清空当前测试类型的记录。两者都对所有分组的全部账户生效。
指纹检测和 SIWC 检测可点击「停止」中断。糖果和鹈鹕测试开始后不能在页面中停止。重启不会继续未完成的测试。

指纹检测每次尝试限时 3 分钟。糖果和鹈鹕测试每次尝试限时 10 分钟。SIWC 检测每次限时 1 分钟。指纹、糖果和鹈鹕测试超时会计入重试。SIWC 超时会直接记录为失败，不会重试。

## 自动巡检

1. 在「糖果」页选择分组。
2. 设置账户筛选条件。
3. 按需设置各账户的「启用自动巡检」开关。
4. 打开「设置」标签页。
5. 开启「自动巡检」。
6. 设置模型、推理强度、检查方式（「糖果」或「指纹」）、每账户最多测试次数、等待范围，以及可选的「包含账户通配符（INCLUDE）」和「排除账户通配符（EXCLUDE）」（按 `path.Match` 匹配账户名称和邮箱）。

设置会自动保存。选择「糖果」检查方式时，回答错误判定为降级；选择「指纹」检查方式时，在完成或部分归因的检测中若预测模型与测试模型（含别名归一）不一致则判定为降级。巡检结果会计入对应测试类型的历史记录，「糖果」页会显示巡检状态、下次巡检时间、账户进度和本轮判定摘要。确认降级的账户会显示「降级」标签。
如需立即运行一轮，可点击「设置」底部的「立即巡检」。自动巡检关闭时也可以使用。

### 模型控制

1. 开启「模型控制」。
2. 在「降级移除模型」中选择模型。

巡检确认账户降级后，会从该账户的允许模型中移除匹配项。账户恢复后，巡检会恢复此前移除的模型。
关闭模型控制或修改移除列表后，恢复仍会使用此前的移除记录。移除模型不会阻断恢复巡检。

### 优先级

1. 开启「优先级」中的自动调整开关。
2. 设置正常优先级。
3. 设置降级优先级。

数值越小，账户优先级越高。降级优先级必须大于正常优先级。模型控制和优先级调整相互独立。
定时巡检和「立即巡检」会应用这些设置。手动单账户和批量测试不会应用这些设置。

### 通知

开启「通知」并配置 ntfy 或 Bark 后，账户被确认降级或恢复正常时会收到通知。两者都配置时会同时发送。通知与优先级调整无关。

## 安装

在本仓库的 [Actions](actions/workflows/build.yml) 中打开一次成功的 `Build` 运行，下载对应平台的 `sub2api-plugins-installer-<upstream_tag>-<os>-<arch>` 并运行。安装方式、注意事项和手动恢复步骤见 [Sub2API-Plugins](https://github.com/Nanboom233/Sub2API-Plugins#installation)。

如需同时安装多个插件，请使用 Sub2API-Plugins 的组合安装器。

### 回退测试记录

首次读取旧格式历史时，程序会在数据目录的 `codex-eval` 下保存 `history.v2.json`、`history.v1.json` 或 `history.v0.json`。安装器的程序备份不包含这些文件。

如需回退到旧程序并保留对应的测试记录：

1. 停止 Sub2API。
2. 另存当前的 `history.json`。
3. 将匹配的旧历史副本恢复为 `history.json`。
4. 按 [Sub2API-Plugins](https://github.com/Nanboom233/Sub2API-Plugins#restore) 中对应安装方式的步骤恢复程序。

旧历史副本不包含升级后新增的记录。
